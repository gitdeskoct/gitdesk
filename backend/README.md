# gitdesk-api

The Cloudflare Worker behind gitdesk. It runs Google OAuth, hands a one-time code to the desktop app, issues and rotates session tokens, and stores remote repository metadata, each repository's storage in R2, and an activity log. With Git hosting on, every repository also gets a private Git URL on Cloudflare Artifacts, and the Worker mints the short-lived tokens Git uses for it. Hono for routing, D1 with Drizzle for metadata, R2 for stored data, Artifacts for Git, jose for JWTs.

See the [root README](../README.md) for how the desktop app and this Worker fit together.

## What it serves

`GET /health`, plus these routes under `/api/v1`.

### Auth (`src/modules/auth/routes.ts`)

| Route | Purpose |
| --- | --- |
| `GET /auth/google/start` | Called by the system browser. Stores an OAuth transaction and redirects to Google. |
| `GET /auth/google/callback` | Google's redirect target. Verifies the sign-in and redirects to the app's loopback with a one-time code. |
| `POST /auth/desktop/exchange` | The app trades the one-time code and its PKCE verifier for tokens. |
| `POST /auth/refresh` | Rotates the refresh token and issues a new access token. |
| `POST /auth/logout` | Revokes the session that owns a refresh token. |
| `GET /auth/me` | The signed-in account. |
| `GET /auth/sessions` | The account's active sessions. |
| `DELETE /auth/sessions/:id` | Revokes one of the account's sessions. |

Access tokens are HS256 JWTs valid for 10 minutes. Refresh tokens are random and stored only as SHA-256 hashes. Sessions end after 30 days without a refresh or 90 days in total. A cron at 03:00 UTC daily (`src/jobs/cleanup.ts`) deletes expired transactions, codes and old sessions, and push records older than 180 days.

### Repositories and activity (`src/modules/repositories`, `src/modules/activity`)

All need a bearer access token and only ever see the caller's own rows. Writes also pass `WRITE_LIMITER`.

| Route | Purpose |
| --- | --- |
| `GET /dashboard/overview` | Repository count, the 5 most recently updated repositories, the 5 latest activity rows, and `gitHosting` (whether this server gives repositories a Git URL). |
| `GET /repositories?sort=updated\|name&limit&cursor` | Keyset-paginated list. `updated` (default) is newest first, `name` is A to Z. A cursor only works with the sort that made it. |
| `GET /repositories/:id` | One repository. |
| `GET /repositories/:id/activity?limit&cursor` | That repository's events, newest first. |
| `POST /repositories` | Creates a repository, at most 200 per account, and sets up its storage. An optional `Idempotency-Key` uuid header makes a retry return the first result. Answers 201 even when storage setup failed: the repository then has status `failed`. |
| `POST /repositories/:id/provision` | Retries storage setup for a `provisioning` or `failed` repository. A `ready` one is returned as is, except that one made before Git hosting was on gets its Git repository here; a `deleting` one is 409 `INVALID_STATE`. |
| `POST /repositories/:id/git-credentials` | Body `{ scope: "read" \| "write", lifetime: 900 \| 3600 \| 28800 }`. Returns `{ remote, token, scope, expiresAt }` for Git over HTTPS. Owner only, `ready` repositories only, through `GIT_LIMITER`. 503 `GIT_HOSTING_UNAVAILABLE` when hosting is off. |
| `DELETE /repositories/:id/git-credentials` | Revokes every token for the repository: `{ revoked }`. |
| `PATCH /repositories/:id` | Changes `name` and/or `description`. 409 `INVALID_STATE` while the repository is being deleted. |
| `DELETE /repositories/:id` | Deletes the stored data and the Git repository (which revokes its tokens), then the row: 204. If cleanup stops partway it answers 202 with the repository, now `deleting`; calling DELETE again resumes it. |
| `GET /activity?limit&cursor` | Every event for the account, newest first. |
| `POST /repositories/:id/sync-events` | The desktop reports a push to the repository's Git URL: `{ operationId, kind: "push", ref, oldOid, newOid }`. The Worker checks Artifacts and answers `{ event: { result, tip } }`: `confirmed` when the pushed commit is stored there, `unverified` when it isn't, hosting is off or Artifacts didn't answer. One row per `operationId`; a retry returns the first answer, and the same id under another repository is 409 `INVALID_STATE`. Through `SYNC_LIMITER`. |

Errors use `{ error: { code, message, requestId } }`; codes are in `src/lib/errors.ts`. Request bodies are capped at 8 KB (413 `PAYLOAD_TOO_LARGE`). The request id is always generated by the Worker and returned in `X-Request-Id`.

### Pull requests (`src/modules/pull-requests`)

Review records for repositories the account owns. A pull request is only ever found through its owner's repository, so another account's id answers 404. Writes pass `PULL_LIMITER`. Bodies on these routes may be up to 64 KB (descriptions and comments run to 10,000 characters).

| Route | Purpose |
| --- | --- |
| `GET /repositories/:repositoryId/pull-requests?status&q&limit&cursor` | Keyset-paginated list, newest activity first, with `counts` per status. `q` matches the title, either branch or `#number`. |
| `POST /repositories/:repositoryId/pull-requests` | Creates one. The number comes from the insert itself; an `Idempotency-Key` returns the first result on a retry. |
| `GET /repositories/:repositoryId/pull-requests/stats?range=3m\|6m\|1y` | Opened and merged per UTC month, counts, median time to merge, open with conflicts. |
| `GET /pull-requests/:id` | One pull request with its latest snapshot, comment counts and newest decision. |
| `PATCH /pull-requests/:id` | Title, description, draft. 409 once merged. |
| `POST /pull-requests/:id/close`, `/reopen` | Never touch branches. A merged pull request is never closed or reopened. |
| `GET`, `POST /pull-requests/:id/reviews` | A review names the snapshot version and commits it saw; one for anything but the latest is 409 `STALE_SNAPSHOT`. |
| `GET`, `POST /pull-requests/:id/comments` | General comments, one-level replies, and line comments with an anchor in an existing snapshot. |
| `PATCH`, `DELETE /pull-requests/:id/comments/:commentId` | Only the author edits or deletes (soft); the owner may resolve any thread. |
| `GET /pull-requests/:id/activity?limit&cursor` | The timeline, newest first. |
| `POST /pull-requests/:id/events` | Events only the desktop knows: merge started, conflicts, aborted, failed, pushed, reverted, branch deleted. |
| `POST /pull-requests/:id/comparisons` | Records a client-computed comparison: a new snapshot when a commit moved, plus an optional mergeability check for it. |
| `POST /pull-requests/:id/merge-result` | Records a verified local merge, idempotent by `operationId`. |
| `GET /pull-requests/:id/merge-state` | Status, merge commit and the last reported result. |

Every OID is a client-reported fact: the Worker checks its shape and that it belongs to a recorded snapshot, but has no Git data to verify it against.

### Repository lifecycle

D1, R2 and the Git host can't commit together, so each repository row records how far its storage got in `status`:

| Status | Meaning |
| --- | --- |
| `provisioning` | The row exists; its storage marker or Git repository isn't made yet. |
| `ready` | Storage is set up under the repository's prefix, and the Git repository exists when hosting is on (`git_remote`). |
| `failed` | Setup stopped. Nothing is lost; `POST /provision` retries it. |
| `deleting` | Deletion started. Edits and setup are refused until it finishes. |

Every repository owns the R2 prefix `repositories/<id>/` (`storage_key`). The server makes it from the id, never from the name, and never sends it to clients. Deletion lists and removes everything under that prefix before it deletes the row, so data is never left behind without a row to retry from. The daily cron also marks `provisioning` rows older than 10 minutes as `failed` and retries `deleting` rows older than 10 minutes, 20 at a time.

### Git hosting (`src/lib/git-host.ts`)

R2 can't speak Git's smart HTTP protocol, so Git data lives in [Cloudflare Artifacts](https://developers.cloudflare.com/artifacts/), one Artifacts repository per gitdesk repository, named by the repository's id (never its name, so a rename keeps the URL). The R2 prefix still holds the `meta.json` marker.

- **The URL** is the `remote` Artifacts returns, `https://<ACCOUNT_ID>.artifacts.cloudflare.net/git/gitdesk/<id>.git`. It is stored in `repositories.git_remote` only after it is checked to be plain https with no user, password, query or fragment, and it is sent to clients as `gitUrl`.
- **Tokens.** Git authenticates with a repository-scoped bearer token from `POST /repositories/:id/git-credentials`: `read` for fetch and clone, `write` for push, 15 minutes for the desktop's own commands, 1 or 8 hours for a command copied to a terminal. The token is returned once, is never stored, logged or recorded as activity, and the response is `Cache-Control: no-store`.
- **Git traffic never passes through the Worker.** Git talks to Artifacts directly, so Worker body and CPU limits don't apply to packs.
- **Turning it on.** `GIT_HOSTING` must be `artifacts` and the `ARTIFACTS` binding present. Artifacts needs the Workers Paid plan and has no local simulator, so `npm run dev` runs with `--local` and `.dev.vars` sets `GIT_HOSTING=off`; `npm run dev:remote` uses the real service. Tests pass a fake host to `createApp`.
- **Limits** (Artifacts, October 2026): 1 GB per repository, push over Git protocol v1, billed from 14 October 2026 at $0.15 per 1,000 operations after 10,000 a month and $0.50 per GB-month after 1 GB.

### Tables

| Table | Holds |
| --- | --- |
| `accounts` | One row per person. |
| `auth_identities` | Google subject linked to an account. |
| `oauth_transactions` | In-flight Google sign-ins. |
| `desktop_auth_codes` | One-time codes the desktop app exchanges for tokens. |
| `sessions` | Refresh token hashes and session lifetimes. |
| `repositories` | Remote repository metadata, unique by case-insensitive name per account, with its lifecycle `status`, `storage_key` and `git_remote`. |
| `activity` | Create, update, delete, storage setup and failed deletion events. Keeps the repository name; `repository_id` is cleared when the repository is deleted. |
| `pull_requests` | Pull request records, numbered per repository, with the latest compared commits. |
| `pull_request_snapshots` | Each comparison version: source, target and merge-base commits, and its mergeability check. |
| `pull_request_reviews`, `pull_request_comments`, `pull_request_comment_anchors` | Review decisions, comments and the snapshot each line comment points at. |
| `pull_request_activity`, `pull_request_merge_results` | The timeline, and one row per reported merge operation. |

## Configuration

| Name | Kind | Where it is set | Used for |
| --- | --- | --- | --- |
| `PUBLIC_ORIGIN` | var | `wrangler.jsonc`: `https://gitdesk-api.telvinteum.workers.dev` (production), `https://gitdesk-api-dev.telvinteum.workers.dev` (`env.dev`); `http://localhost:8787` in `.dev.vars` and `vitest.config.ts` | Google redirect URI and JWT issuer |
| `GIT_HOSTING` | var | `wrangler.jsonc` (`off`, because the account is on the free plan), `off` in `.dev.vars` | Whether repositories get a Git URL |
| `SYNC_LIMITER` | Rate limit binding | `wrangler.jsonc`, namespace 4107 (production) or 5107 (`env.dev`), 60 a minute per account | Push reports |
| `ARTIFACTS` | Artifacts binding | `wrangler.jsonc`, commented out until the account is on Workers Paid (a free-plan deploy with it is refused, code 10403) | Git repositories and their tokens |
| `GOOGLE_CLIENT_ID` | secret | `.dev.vars` locally, `wrangler secret put` remotely | Google OAuth client |
| `GOOGLE_CLIENT_SECRET` | secret | `.dev.vars` locally, `wrangler secret put` remotely | Google OAuth client |
| `JWT_SIGNING_KEY` | secret | `.dev.vars` locally, `wrangler secret put` remotely | Signing access tokens. At least 32 bytes, base64url; production, dev and local each use their own 64-byte key. |
| `DB` | D1 binding | `wrangler.jsonc`, database `gitdesk-db` (production) or `gitdesk-db-dev` (`env.dev`), both Western Europe | Accounts, identities, transactions, codes, sessions, repositories, pull requests |
| `REPO_STORAGE` | R2 binding | `wrangler.jsonc`, bucket `gitdesk-repositories` (production) or `gitdesk-repositories-dev` (`env.dev`) | Each repository's stored data under `repositories/<id>/`. Create the bucket with `npx wrangler r2 bucket create gitdesk-repositories` before deploying. |
| `AUTH_LIMITER` | rate limit binding | `wrangler.jsonc` | Sign-in routes, 10 requests per 60 seconds per IP and route |
| `REFRESH_LIMITER` | rate limit binding | `wrangler.jsonc` | Token refresh and logout, 20 requests per 60 seconds per IP |
| `API_LIMITER` | rate limit binding | `wrangler.jsonc` | Every signed-in request, 120 per 60 seconds per account |
| `WRITE_LIMITER` | rate limit binding | `wrangler.jsonc` | Repository writes, 10 per 60 seconds per account, to protect D1's daily row-write quota |
| `GIT_LIMITER` | rate limit binding | `wrangler.jsonc` | Git tokens, 30 per 60 seconds per account. The desktop reuses a token until a minute before it expires. |
| `PULL_LIMITER` | rate limit binding | `wrangler.jsonc` | Pull request writes, 60 per 60 seconds per account |

`PUBLIC_ORIGIN` is an origin with no trailing slash, because the code appends `/api/v1/auth/google/callback` to it.

## Setup

Run everything in `backend/`.

### 1. Install

```bash
npm install
```

### 2. Create a Google OAuth client

In the Google Cloud console, under APIs & Services, Credentials, create an **OAuth client ID** of type **Web application**. The Worker, not the desktop app, is the OAuth client, which is why the type is Web application and not Desktop.

Add one authorized redirect URI per origin the Worker runs on, in the form `<PUBLIC_ORIGIN>/api/v1/auth/google/callback`:

- Local: `http://localhost:8787/api/v1/auth/google/callback`
- Production: `https://<your-worker-origin>/api/v1/auth/google/callback`

The Worker requests the `openid email profile` scopes, so the OAuth consent screen needs those. Copy the client ID and client secret for the next steps.

### 3. Local secrets

Copy the example file and fill it in. `.dev.vars` is gitignored.

```bash
cp .dev.vars.example .dev.vars
```

Generate `JWT_SIGNING_KEY` with:

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('base64url'))"
```

### 4. Local database and dev server

```bash
npm run db:migrate:local
```

```bash
npm run dev
```

The Worker listens on `http://localhost:8787`. Point the desktop app at it with `VITE_API_ORIGIN=http://localhost:8787` in the root `.env`.

### 5. Tests

```bash
npm test
```

Tests run inside the Workers runtime through `@cloudflare/vitest-plugin`. They apply the migrations to a fresh D1 database and use test secrets from `vitest.config.ts`, so they need neither `.dev.vars` nor a Cloudflare account. They set `PUBLIC_ORIGIN` to `http://localhost:8787` themselves, whatever production uses.

## Deploy

Two Workers on account `5b14dbcfcd4e8acdb4bad6aff07ce149`, from one `wrangler.jsonc`:

| | Production (top level) | Dev (`env.dev`) |
| --- | --- | --- |
| URL | `https://gitdesk-api.telvinteum.workers.dev` | `https://gitdesk-api-dev.telvinteum.workers.dev` |
| Worker | `gitdesk-api` | `gitdesk-api-dev` |
| D1 | `gitdesk-db` | `gitdesk-db-dev` |
| R2 | `gitdesk-repositories` | `gitdesk-repositories-dev` |
| Rate-limit namespaces | 4101–4106 | 5101–5106 |
| Traces sampled | 5% | 100% |
| Deploy | `npm run deploy` | `npm run deploy:dev` |
| Migrate | `npm run db:migrate:remote` | `npm run db:migrate:dev` |
| Live logs | `npm run tail` | `npm run tail:dev` |

Environments inherit no bindings or vars, so `env.dev` restates every one; nothing it does reaches production data. Both run the daily cleanup cron (`0 3 * * *`), have `workers.dev` on and preview URLs off, and refuse plain `http://` with 403 `HTTPS_REQUIRED`. The scripts pass `--env=` for production so Wrangler never has to guess.

### Deploying a change

Try it on dev, then production. Apply any new migration before the code that needs it. Secrets carry over between deploys.

```bash
npm run db:migrate:dev
```

```bash
npm run deploy:dev
```

```bash
npm run db:migrate:remote
```

```bash
npm run deploy
```

### Secrets

Both environments share the Google OAuth client, and each has its own random 64-byte `JWT_SIGNING_KEY`, so a token from one is worthless on the other. Secrets can be replaced but never read back. Each command prompts for the value; use `--env dev` for dev:

```bash
npx wrangler secret put GOOGLE_CLIENT_ID --env=
```

```bash
npx wrangler secret put GOOGLE_CLIENT_SECRET --env=
```

Rotating `JWT_SIGNING_KEY` signs everyone in that environment out at their next request. Generate a key with `node -e "console.log(require('crypto').randomBytes(64).toString('base64url'))"` and set it:

```bash
npx wrangler secret put JWT_SIGNING_KEY --env=
```

The Google client must list every callback as an authorized redirect URI, or Google stops sign-in with `redirect_uri_mismatch`:

- `https://gitdesk-api.telvinteum.workers.dev/api/v1/auth/google/callback`
- `https://gitdesk-api-dev.telvinteum.workers.dev/api/v1/auth/google/callback`
- `http://localhost:8787/api/v1/auth/google/callback`

### Observability

Both log every request (query strings redacted, because the Google callback carries a one-time code), persist logs and traces, and have [Workers Issues](https://developers.cloudflare.com/workers/observability/issues/) on. Issues groups uncaught exceptions and the `console.error` the error handler writes for unhandled errors, which carries the error itself so it is grouped by its stack. Find them in the dashboard under each Worker's Observability and Issues tabs.

### Turning on Git hosting

Artifacts needs Workers Paid. After upgrading: uncomment the `artifacts` binding in `wrangler.jsonc` (and add it to `env.dev`), set `GIT_HOSTING` to `artifacts` in both, run `npm run cf-typegen` and deploy both. Repositories created while hosting was off get their Git URL from the backfill on their next read.

### Pointing the desktop app at a Worker

Set `VITE_API_ORIGIN` in the root `.env`: production by default, the dev URL to try backend changes from the app. Packaged builds accept only an https origin.

### Setting up a new account from scratch

1. `npx wrangler d1 create gitdesk-db` and `npx wrangler d1 create gitdesk-db-dev`, and put each `database_id` in `wrangler.jsonc`.
2. `npx wrangler r2 bucket create gitdesk-repositories` and `npx wrangler r2 bucket create gitdesk-repositories-dev`.
3. Set both `PUBLIC_ORIGIN` values to your `workers.dev` subdomain.
4. `npm run db:migrate:remote` and `npm run db:migrate:dev`.
5. Deploy each once with its three secrets, so the required-secrets check passes: `npx wrangler deploy --minify --env= --secrets-file <file>` and the same with `--env dev`, each with a JSON file of `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET` and `JWT_SIGNING_KEY`. Delete the files afterwards.

## Changing the schema

1. Edit `src/db/schema.ts`.
2. Generate a migration into `drizzle/migrations`:

```bash
npm run db:generate
```

3. Apply it with `npm run db:migrate:local`, and `npm run db:migrate:remote` before deploying code that depends on it.

If you change bindings in `wrangler.jsonc`, regenerate the binding types in `worker-configuration.d.ts`:

```bash
npm run cf-typegen
```
